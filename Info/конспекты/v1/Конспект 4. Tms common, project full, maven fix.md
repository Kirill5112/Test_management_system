## 2. Модуль `tms-common`
Предназначен для общих сущностей, не привязанных к конкретному сервису.

**Зависимости (ВАЖНО!):**
`jakarta.servlet-api` и `spring-tx` (для `DataIntegrityViolationException`) добавлены со scope **`provided`**. В рантайме они придут из `starter-web` и `starter-data-jpa` сервисов-потребителей.

**Содержимое:**
- `enums`: `UserRole`, `ProjectStatus`, `ProjectRole`, `TestCasePriority`, `TestCaseType`, `TestCaseStatus`, `TestRunStatus`, `TestResultStatus`, `BugStatus`, `BugSeverity`, `BugPriority`.
- `dto`: `ErrorResponse`, `PageResponse`.
- `exception`: `ApiException`, `ResourceNotFoundException`, `ConflictException`, `BadRequestException`, `GlobalExceptionHandler`.
- `consts`: `KafkaTopics` (константа `test-run-events`).
- `event`: `TestRunFinishedEvent` (record).
- `autoconfig`: `CommonAutoConfiguration` + файл `META-INF/spring/...AutoConfiguration.imports`.

**⚠️ Проблема с автоконфигурацией:**
Файл `AutoConfiguration.imports` не подхватился (скорее всего, из-за структуры сборки Maven/IDEA). 
**Решение:** В главные классы `@SpringBootApplication` бизнес-сервисов добавлен `@Import(CommonAutoConfiguration.class)`. Это гарантированно регистрирует `GlobalExceptionHandler` в контексте.

## 3. Вертикальный слайс `Project` (test-repository-service)
Реализован по схеме: `Entity → Repository → Mapper (MapStruct) → Service → Controller → DTO`.

- **Entity `Project`**: Поля `id`, `key`, `name`, `description`, `ownerId` (скалярный `UUID`, **без `@ManyToOne`**), `status`, `createdAt/updatedAt` (`OffsetDateTime`).
- **DTO**: `ProjectCreateRequest` (валидация `@Pattern` для key), `ProjectUpdateRequest`, `ProjectResponse`.
- **Service**: Бизнес-логика (проверка на дубликат `key` через `existsByKey`).
- **Controller**: `POST /projects`, `GET /projects` (с фильтрацией и пагинацией), `GET /projects/{id}`, `GET /projects/by-key/{key}`, `PUT /projects/{id}`, `DELETE /projects/{id}`.
- **FK Constraint**: При создании проекта с несуществующим `ownerId` БД выбрасывает `DataIntegrityViolationException`, который перехватывается глобальным хэндлером и возвращает `409 Conflict`.

## 4. Решённые проблемы (не наступить снова)

### 4.1. Lombok и MapStruct не работали в Maven
**Симптом:** `cannot find symbol` (нет геттеров/сеттеров) и `variable ... not initialized in default constructor`.
**Причина:** В `pom.xml` сервисов был явно объявлен `maven-compiler-plugin` с `<annotationProcessorPaths>`, где был только `spring-boot-configuration-processor`. Maven игнорирует процессоры из `classpath`, если этот блок задан.
**Решение:** В `maven-compiler-plugin` добавлены **все 4** процессора в строгом порядке:
1. `spring-boot-configuration-processor`
2. `lombok`
3. `lombok-mapstruct-binding` (версия `0.2.0`)
4. `mapstruct-processor`
Блок `<executions>` убран (чтобы конфигурация применялась по умолчанию ко всем фазам).

### 4.2. Ошибки БД возвращали 500 вместо 409
**Причина:** `AutoConfiguration.imports` не сработал.
**Решение:** Явный `@Import(CommonAutoConfiguration.class)` в главных классах сервисов.
